# Автоосмотр — калькулятор

Local-first PWA для оценки подержанного автомобиля прямо во время осмотра. Базовый каталог: Toyota Corolla E120 1.6 AT, Kia Cerato LD 1.6 AT и Chevrolet Lacetti Hatch 1.6 AT. В настройках можно добавить свои модели, варианты двигателя, события ремонта и шаблоны осмотра.

Приложению не нужен backend. Осмотры хранятся в IndexedDB текущего браузера, перенос между устройствами — через «Экспорт» и «Импорт» JSON.

## Запуск

```bash
pnpm install
pnpm dev
```

## Проверки

```bash
pnpm run verify     # формат + линт + типы + тесты
pnpm test           # только тесты
pnpm run typecheck  # только типы
pnpm build          # production-сборка
```

Те же проверки выполняет CI перед деплоем на GitHub Pages.

> При первом `pnpm install` после обновления зависимостей лок-файл перезапишется — его нужно закоммитить. После этого в `.github/workflows/deploy.yml` можно вернуть `pnpm install --frozen-lockfile` вместо `--no-frozen-lockfile`.

## Публикация

Сборка рассчитана на подпапку GitHub Pages: `base` по умолчанию `/auto-inspection-calculator/`. Для публикации в корень своего домена достаточно переменной окружения:

```bash
APP_BASE=/ pnpm build
```

Все пути PWA (манифест, иконка, регистрация service worker) строятся от `base`, поэтому смена адреса не ломает офлайн-режим.

## Структура

```
src/
  calculator.ts          расчёт: смета, прогноз, симуляция рисков, рейтинг
  config.ts              seed-конфигурация: модели, коэффициенты, события
  storage.ts             IndexedDB, журнал несохранённых правок, нормализация конфигурации
  backup.ts              экспорт/импорт резервной копии с валидацией
  domain/inspection.ts   создание осмотра, шаблоны, варианты двигателя
  state/useAppData.ts    состояние приложения и отложенная запись на диск
  labels.ts              подписи интерфейса
  ui/                    диалог подтверждения и уведомления
  components/            переиспользуемые элементы формы и редакторы
  views/                 экраны приложения
```

## Важные правила модели

- Факт «под вопросом» всё равно входит в безопасную смету.
- Срочные работы входят в текущий бюджет сразу; «в ближайшее время», «планово» и «желательно» показываются отдельными суммами и переносятся в прогноз на 3, 9 и 18-й месяцы.
- Состояния вроде «АКПП исправна» сохраняются как факты без стоимости.
- Осмотр проходит по этапам и конкретным элементам: кузов, салон, двигатель, АКПП, ходовая, электрика и другие блоки. После сохранения элемент остаётся в общем журнале фактов.
- При создании осмотра выбирается вариант двигателя и тип привода ГРМ: для Corolla seed-профиль использует цепь, для Cerato и Lacetti — ремень; вариант «код двигателя не установлен» оставляет решение открытым до проверки по VIN.
- Свободные факты можно объединять в именованные блоки и дублировать одним нажатием.
- Структуру осмотра можно менять прямо в карточке автомобиля: добавлять, переименовывать и удалять этапы, подблоки и элементы.
- В прогнозе любую работу можно отключить, изменить или удалить. Новые работы добавляются как вероятностные события или как обязательные работы с известным сроком после покупки.
- Безопасная стоимость работы — заявленная стоимость, умноженная на коэффициент категории. Отрицательная стоимость не принимается.
- Кузовные риски делятся на два класса. Критические (силовая коррозия, лонжероны, стаканы, днище, крепления подвески, геометрия, тяжёлое ДТП, масштабная сварка, неопределимый объём) останавливают расчёт и не заменяются денежной сметой. Остальные — например отдельный порог с потерей прочности — дают предупреждение и считаются обычной оцениваемой работой.
- ДТП, тип ПТС и количество ключей не создают автоматический отказ, но влияют на компонент рейтинга «История и комплектность».
- Пятилетние расходы и полная стоимость с покупкой/доведением отображаются раздельно.
- Вероятности ремонтов являются редактируемыми модельными параметрами, а не заявленной статистикой.
- Симуляция детерминирована: зерно собирается из численных параметров событий (вероятность, стоимость, коэффициент, максимум, окно), поэтому переименование события не меняет результат. По умолчанию считается 4000 сценариев — точность вероятности около ±0,8 п.п.
- Факты «под вопросом» дают отдельный показатель определённости, но не повышают риск автоматически: приложение не подменяет отсутствие данных выдуманной вероятностью.
- Факты «под вопросом» с указанной стоимостью участвуют в безопасной смете, а неопределённые состояния без цены переводят результат в предварительный статус без искусственного штрафа.
- Прогноз раскрывается по годам и месяцам: бензин, ОСАГО, налог, ТО, жидкости, расходники, резина, мойка и штрафы показаны раздельно от ремонта.
- Для каждого ремонта резерв копится до его срока, трата показывается в месяце события, а после события его отчисление прекращается. «Плановый бюджет» и «Ожидаемо всего» поэтому имеют разный смысл.
- Горизонт прогноза приводится к диапазону 1–15 лет: испорченная конфигурация из чужого файла не должна превращать рейтинг в `NaN`.
- В настройках модели можно редактировать классические потенциальные события, отключать и удалять их, а также добавлять свои работы с вероятностью или известным сроком.
- Подробное описание методики доступно в разделе «FAQ» внутри приложения.

## Данные и сохранность

- Каждый осмотр хранит снимок конфигурации, с которой он считался. Шаблоны форм в снимок не пишутся — они одинаковы для всех осмотров и восстанавливаются при загрузке.
- Запись на диск отложенная (500 мс). Статус сохранения виден в шапке; ошибка записи показывается явно, а не проглатывается, и данные возвращаются в очередь.
- Каждое изменение синхронно попадает в журнал в localStorage и удаляется оттуда только после подтверждённой записи в IndexedDB. Это защита от единственного случая, который иначе теряет данные: перезагрузка или закрытие вкладки в первые полсекунды после правки — запись в IndexedDB асинхронная и не успевает завершиться. При следующем запуске журнал применяется поверх базы.
- Импорт резервной копии проверяет `schemaVersion` и структуру файла, чинит повреждённые поля и полностью заменяет содержимое хранилища — состояние в памяти и в базе не расходятся.

Seed-значения расходов и ремонтных событий предназначены для настройки пользователем. Перед реальным решением их следует заменить собственными оценками специалиста и актуальными затратами.
