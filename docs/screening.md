# Этап 1: отбор по выдаче объявлений

Приложение считает осмотр. До осмотра есть более дешёвый шаг: прогнать всю выдачу
объявлений через тот же расчёт и оставить машины, ради которых стоит звонить и ехать.

```bash
pnpm screening ~/Downloads/автоосмотр-backup-2026-08-29.json ~/Downloads/avito.html --discount 20000
```

На выходе — файл `…-screening.json` рядом с исходным экспортом и таблица в консоли.
Файл импортируется в приложении кнопкой «Импорт».

## Порядок работы

1. **Экспорт из приложения.** Импорт заменяет все данные целиком, поэтому в работу идёт
   свежий экспорт: скрипт кладёт новые осмотры внутрь него, сохраняя настройки и прежние
   осмотры без изменений.
2. **Сохранение страницы выдачи.** В браузере `Cmd+S` → «Веб-страница, только HTML».
   Ссылки на объявления есть только в HTML: из скопированного текста их не достать, а без
   ссылки машину нельзя будет дополнить на втором этапе.
3. **Прогон.** Скрипт разбирает карточки, отсеивает чужие поколения, собирает осмотры и
   печатает таблицу по убыванию рейтинга.
4. **Импорт** полученного файла в приложении и разбор в интерфейсе.
5. **Второй этап.** По заинтересовавшим машинам открывается деталка, факты дописываются
   руками в приложении либо повторным прогоном с ключом `--merge`.

## Ключи

| Ключ | Что делает |
| --- | --- |
| `--out <файл>` | Куда записать результат. По умолчанию — рядом с экспортом, с суффиксом `-screening`. |
| `--merge` | Дополнять осмотр с той же ссылкой, а не пропускать его. Факты по перечисленным элементам заменяются, остальные сохраняются, `id` осмотра не меняется. |
| `--no-wear` | Не добавлять вопросы, выведенные из пробега и возраста. |
| `--discount <₽>` | Ожидаемый торг для всех машин пачки. |
| `--source <имя>` | Площадка, если это не avito. |

Повторный прогон той же страницы без `--merge` ничего не портит: машины с уже известными
ссылками пропускаются и попадают в отдельный список.

## Что скрипт берёт из объявления, а что нет

Объявление — не осмотр. Поэтому:

- **Работа** (`kind: WORK`, с деньгами в смете) заводится только там, где дефект назван в
  тексте прямо: «течет масло», «АКПП пинается», «порог подваривали». В комментарий факта
  попадает цитата-источник.
- **«Исправно»** не ставится никогда. По объявлению ничего не проверено.
- Всё остальное — **«под вопросом»**: заявления продавца («не бита, не крашена»), молчание
  объявления о ГРМ и масле АКПП при большом пробеге, возраст за 15 лет. Такой факт не
  добавляет денег в смету, а даёт список вопросов на звонок и точки внимания на осмотре.
- **Стоимость не выдумывается.** Работа сохраняется без цены, и приложение подставляет
  вилку из справочника «запчасти + нормо-часы × ставка».
- **Тип ПТС, число ключей и ДТП** читаются из текста и влияют на компонент рейтинга
  «История и комплектность». Слова «не бита, не крашена» оставляют статус ДТП неизвестным:
  это заявление продавца, а не отчёт.
- **Вариант двигателя остаётся неизвестным**: код читается по VIN и маркировке на блоке,
  в объявлении его нет. Поэтому элемент ГРМ на этом этапе называется «ГРМ: уточнить тип и
  состояние».

Правила разбора лежат в [`src/importers/rules.ts`](../src/importers/rules.ts):
`TEXT_RULES` — по тексту объявления, `WEAR_RULES` — по пробегу и возрасту, `GENERATIONS` —
годы выпуска поколений. Их стоит править под себя: это рабочие эвристики, а не истина.

## Отсев по модели

Машина попадает в файл, только если совпали марка, модель, объём, коробка и год входит в
годы поколения. Kia Cerato 2012 года — это уже LD-преемник TD с другой сметой, поэтому
такое объявление уходит в список «вне модельного ряда» с указанием причины, а не
подставляется в ближайшую модель.

Тип кузова в заголовке выдачи Avito не указан, поэтому для Lacetti добавляется отдельный
вопрос: хэтчбек это или седан.

## Устройство

| Файл | Ответственность |
| --- | --- |
| [`src/importers/avito.ts`](../src/importers/avito.ts) | HTML выдачи → список объявлений. Опора на `data-marker`, `data-item-id`, `itemprop` и `alt`: хешированные классы Avito меняются между релизами. |
| [`src/importers/rules.ts`](../src/importers/rules.ts) | Объявление → модель, факты и данные автомобиля. |
| [`src/importers/listings.ts`](../src/importers/listings.ts) | Список машин → осмотры внутри экспорта. Валидация: ошибка в одном объявлении отменяет всю пачку, файл не пишется. |
| [`tools/screening.ts`](../tools/screening.ts) | CLI и отчёт. |
| [`tools/ts-resolve.mjs`](../tools/ts-resolve.mjs) | Хук Node: исходники импортируют модули без расширения, как их видит Vite. |

Скрипт работает на исходниках приложения напрямую (`node --experimental-strip-types`),
без сборки и без своей копии расчёта: осмотры создаются той же функцией `makeInspection`,
факты — в том же формате, что пишет экран осмотра, а таблица считается тем же
`calculateInspection`, что и в приложении.
