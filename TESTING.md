# План проверки версии 1.0.0

Проверки идут от самого рискованного к самому спокойному: сначала то, что появилось заново и ни разу не запускалось вживую, потом изменения в расчёте, потом PWA и деплой.

Отмечайте пункты прямо здесь — то, что не сошлось, станет списком доработок.

## 0. Запуск

```bash
pnpm dev
```

Открыть **http://127.0.0.1:5173/auto-inspection-calculator/** (адрес с подпапкой — база задана в `vite.config.ts`).

- [ ] Приложение открылось, экран «Осмотры автомобилей» на месте
- [ ] В консоли браузера (F12 → Console) нет красных ошибок
- [ ] Старые осмотры, если они были, на месте и считаются

> Если осмотры пропали — остановиться и написать об этом: значит, сломалась миграция снимка конфигурации.

## 1. Новые механизмы интерфейса

Их раньше не было вообще, поэтому риск здесь самый высокий.

### 1.1 Диалог подтверждения (заменил `window.confirm`)

Семь мест: удаление осмотра, факта, состояния элемента этапа, этапа формы, подблока формы, события в прогнозе, модели и шаблона в настройках.

- [ ] Диалог появляется по центру, фон затемняется
- [ ] «Отмена» — ничего не удаляется
- [ ] Клик по затемнённому фону — то же самое, что «Отмена»
- [ ] Esc закрывает диалог и ничего не удаляет
- [ ] «Удалить» — объект действительно исчезает
- [ ] Проверить минимум в трёх разных местах из семи

### 1.2 Уведомления (заменили `window.alert`)

- [ ] «Экспорт» → внизу появляется зелёное «Резервная копия выгружена», файл скачался
- [ ] Уведомление само исчезает через несколько секунд, крестик закрывает его сразу
- [ ] «Импорт» → выбрать любой посторонний файл (например `package.json`) → красное уведомление с внятным текстом, данные не пострадали

### 1.3 Индикатор сохранения

- [ ] При изменении любого поля в шапке появляется «Сохраняю…», затем «Сохранено»
- [ ] «Сохранено» исчезает через пару секунд, а не висит постоянно

### 1.4 Отложенная запись — главный тест на потерю данных

- [ ] Открыть «Настройки», изменить любое число (например «Штрафы, год 1») и **сразу** нажать F5
- [ ] После перезагрузки новое значение на месте
- [ ] То же самое с фактом осмотра: сохранить факт и немедленно перезагрузить страницу

Проверено при разработке: раньше правка терялась, потому что запись в IndexedDB
асинхронная и не успевала завершиться до выгрузки страницы. Сейчас каждое
изменение синхронно пишется в журнал `localStorage` и восстанавливается при
следующем запуске. Если что-то всё же потерялось — это баг, о нём нужно сказать.

Заглянуть внутрь можно в DevTools → Application → Local Storage → ключ
`auto-inspection-pending-v1`: он должен появляться в момент правки и пропадать
через полсекунды, когда запись в IndexedDB подтверждена.

## 2. Экспорт и импорт

Раньше импорт оставлял в базе старые записи, и они возвращались после перезагрузки.

1. [ ] Создать два осмотра, нажать «Экспорт»
2. [ ] Создать третий осмотр
3. [ ] «Импорт» → выбрать выгруженный файл
4. [ ] Приложение спрашивает подтверждение и показывает, сколько осмотров в файле и сколько сейчас
5. [ ] После импорта видно ровно два осмотра
6. [ ] **Нажать F5 — по-прежнему ровно два.** Появился третий → баг вернулся
7. [ ] Открыть импортированный осмотр: факты, цены и рейтинг совпадают с тем, что было до экспорта

## 3. Изменения в расчёте

### 3.1 Кузовные риски разделены на два класса

В факте с категорией «Кузов» отмечаются риски.

- [ ] В списке рисков критические помечены знаком «!» и выделены цветом
- [ ] Отметить **«Порог с потерей прочности»** (без «!») → в сводке появляется блок «На что обратить внимание» с записью про оцениваемую кузовную работу, расчёт продолжает считаться
- [ ] Отметить **«! Лонжероны»** → в сводке появляется красный блок «Что останавливает расчёт», ниже — «Критическая точка», в списке осмотров статус «Есть блокирующие риски»

### 3.2 Отрицательные и пустые суммы

- [ ] В поле стоимости не получается ввести минус стрелками (стоит `min="0"`)
- [ ] Если вставить `-50000` из буфера — смета не уходит в минус и зона не становится зелёной
- [ ] Работа без стоимости даёт блокировку «Есть работа без оценённой стоимости — смета неполная»

### 3.3 Полная стоимость владения

- [ ] В карточке автомобиля указать фактическую цену покупки, затем стереть её в ноль
- [ ] «Полная стоимость» в прогнозе всё равно включает цену автомобиля (раньше при нуле она пропадала)

### 3.4 Повторяемость

- [ ] В настройках переименовать любое потенциальное событие
- [ ] Вероятности в прогнозе и рейтинг **не изменились**
- [ ] Изменить вероятность того же события — числа изменились

### 3.5 Отзывчивость

- [ ] Быстро печатать в поле стоимости факта — цифры появляются без задержки
- [ ] Список осмотров с 5–10 карточками открывается мгновенно

## 4. PWA и офлайн

Service worker включается только в production-сборке, поэтому тут нужен `preview`, а не `dev`.

```bash
pnpm build && pnpm preview
```

Открыть **http://localhost:4173/auto-inspection-calculator/**, затем F12 → вкладка **Application**:

- [ ] **Manifest** — читается без ошибок, иконка отображается, `start_url` и `scope` указывают на `/auto-inspection-calculator/`
- [ ] **Service Workers** — статус `activated and is running`, в источнике виден `sw.js?v=1.0.0-...`
- [ ] **Cache Storage** — один кэш вида `auto-inspection-1.0.0-...`
- [ ] Вкладка **Network** → поставить **Offline** → F5 → приложение открывается и работает, осмотры на месте

### Проверка обновления (главная причина, по которой SW переписан)

1. [ ] Изменить что-нибудь заметное в интерфейсе (например заголовок в `HistoryView`)
2. [ ] `pnpm build`, обновить страницу два раза
3. [ ] Изменение видно
4. [ ] В **Cache Storage** остался **один** кэш с новой версией, старый удалён

Если после пересборки видна старая версия — это тот самый баг, и он не закрыт.

## 5. Телефон

Установку на домашний экран честно проверять только по HTTPS: с `http://192.168.x.x` браузер не даст зарегистрировать service worker. Поэтому:

1. [ ] `git push` в `main`, дождаться зелёного CI
2. [ ] Открыть страницу GitHub Pages с телефона
3. [ ] Меню браузера → «На экран «Домой»»
4. [ ] Приложение открывается из иконки в полноэкранном режиме, без адресной строки
5. [ ] Включить авиарежим → приложение по-прежнему открывается
6. [ ] Пройти реальный осмотр: создать карточку, заполнить два-три этапа, посмотреть прогноз

Быстрый черновой прогон в локальной сети (без установки, только интерфейс):

```bash
pnpm preview --host
```
